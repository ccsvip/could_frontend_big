# 07. 开发环境配置指南

> 本文档面向新加入项目的开发者，介绍如何在本地基于 Docker Compose 拉起完整开发环境，以及在不使用容器时的裸机配置方式与常见排障思路。所有命令默认在 Windows PowerShell 下执行，Linux/macOS 同学请自行替换路径分隔符。

---

## 7.1 环境前置要求

### 7.1.1 硬件与系统

| 项目 | 最低要求 | 推荐 |
|------|----------|------|
| CPU | 4 核 | 8 核及以上 |
| 内存 | 8 GB | 16 GB 及以上 |
| 磁盘 | 20 GB 可用空间 | SSD 50 GB 及以上 |
| 操作系统 | Windows 10/11、macOS 12+、Ubuntu 20.04+ | Windows 11 / Ubuntu 22.04 |

### 7.1.2 必装软件

| 软件 | 版本要求 | 用途 |
|------|----------|------|
| Docker Desktop | 4.30+（含 Compose v2） | 容器化运行所有服务 |
| Git | 2.40+ | 版本控制、触发 GitNexus 钩子 |
| Node.js | 20+（仅裸机前端开发需要） | 前端构建 |
| Python | 3.13+（仅裸机后端开发需要） | 后端运行 |
| VS Code / WebStorm | 最新版 | 推荐 IDE |

> **强约束**：本项目的开发、运行、验证以 **Docker Compose** 为准。不要假设宿主机 Python / Node / PostgreSQL / Redis / MinIO 环境与容器一致，所有命令优先在容器内执行。

### 7.1.3 网络与镜像源

构建镜像默认使用国内镜像源以加速拉取，相关变量可在根目录 `.env` 中覆盖：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PYTHON_BASE_IMAGE` | `docker.m.daocloud.io/library/python:3.13` | 后端基础镜像 |
| `NODE_BASE_IMAGE` | `docker.m.daocloud.io/library/node:20-alpine` | 前端基础镜像 |
| `POSTGRES_IMAGE` | `pgvector/pgvector:pg16` | 数据库镜像（必须带 pgvector） |
| `REDIS_IMAGE` | `docker.m.daocloud.io/library/redis:7-alpine` | 缓存镜像 |
| `CADDY_IMAGE` | `docker.m.daocloud.io/library/caddy:2-alpine` | 反向代理镜像 |
| `APT_MIRROR` | `https://mirrors.aliyun.com/debian` | 容器内 apt 源 |
| `APT_SECURITY_MIRROR` | `https://mirrors.aliyun.com/debian-security` | 容器内 apt 安全源 |
| `PIP_INDEX_URL` | `https://pypi.tuna.tsinghua.edu.cn/simple` | 容器内 pip 源 |

## 7.2 获取代码与首次配置

### 7.2.1 克隆仓库

```powershell
git clone <repo-url> could_frontend
cd could_frontend
```

### 7.2.2 配置 Git Hooks（每个 clone 必须执行一次）

项目通过 `.githooks/` 目录托管 Git 钩子，包含两类：

| 钩子 | 作用 |
|------|------|
| `pre-commit` | 调用 `scripts/check-tailwind-tokens.js`，拦截新增的 `!` 前缀 Tailwind 类与 `teal-*` 色阶（仅拦截净增量） |
| `post-commit` / `post-merge` / `post-rewrite` / `post-checkout` / `post-applypatch` / `gitnexus-update` | 自动触发 GitNexus `analyze --index-only` 增量更新代码知识图谱 |

启用方式：

```powershell
git config core.hooksPath .githooks
```

> 未配置 `core.hooksPath` 时，pre-commit 守卫与 GitNexus 自动索引均不会生效。新 clone 必须执行一次。

### 7.2.3 配置根目录 `.env`（端口映射）

根目录 `.env` 用于覆盖 docker-compose 中的端口映射变量，避免与宿主机已有服务冲突。默认值：

```env
WEB_PORT=5175
API_PORT=8880
DB_PORT=5433
REDIS_PORT=6580
```

如默认端口被占用，可改为本机空闲端口。HTTP/HTTPS 入口默认 80/443，可通过 `HTTP_PORT` / `HTTPS_PORT` 覆盖。

### 7.2.4 配置后端 `backend/.env`

后端所有运行时配置通过 `backend/.env` 注入。`config/settings/base.py` 会在启动时读取该文件并把键值写入 `os.environ`。**必须**配置的关键变量：

| 变量 | 说明 | 示例 |
|------|------|------|
| `DATABASE_URL` | **必填**，PostgreSQL 连接串。未设置会抛 `ImproperlyConfigured` | `postgres://postgres:postgres@db:5432/conai` |
| `DJANGO_SECRET_KEY` | Django 密钥 | 随机长字符串 |
| `DJANGO_DEBUG` | 是否开启调试模式（`1`/`0`） | `1` |
| `DJANGO_ALLOWED_HOSTS` | 允许的 Host，逗号分隔 | `*` 或 `localhost,127.0.0.1` |
| `REDIS_URL` | Redis 连接串（缓存与 Celery broker 共用基础） | `redis://redis:6379/0` |
| `REDIS_CACHE_URL` | 缓存专用 Redis（默认回退 `REDIS_URL`） | `redis://redis:6379/0` |
| `CELERY_BROKER_URL` | Celery broker（默认回退 `redis://localhost:6379/1`） | `redis://redis:6379/1` |
| `MULTIMODAL_API_KEY` / `DASHSCOPE_API_KEY` | 阿里云百炼 / DashScope 通用密钥，TTS/ASR/Embedding 共用 | sk-xxx |
| `ALIYUN_TTS_API_KEY` | TTS 专用密钥（回退到 `DASHSCOPE_API_KEY`） | sk-xxx |
| `ALIYUN_EMBEDDING_API_KEY` | Embedding 专用密钥（回退到 `DASHSCOPE_API_KEY`） | sk-xxx |
| `ALIYUN_RERANK_API_KEY` | Rerank 专用密钥（回退到 `DASHSCOPE_API_KEY`） | sk-xxx |
| `JWT_ACCESS_MINUTES` | Access Token 有效期（分钟） | `30` |
| `JWT_REFRESH_DAYS` | Refresh Token 有效期（天） | `7` |
| `BAILIAN_CREDENTIAL_ENCRYPTION_KEY` | 百炼凭证加密密钥 | 32 字节密钥 |
| `FEISHU_WEBHOOK_URL` / `FEISHU_WEBHOOK_SECRET` | 飞书机器人通知（可选） | https://... |

完整变量清单参见 `backend/config/settings/base.py` 顶部的 `os.getenv(...)` 调用。

### 7.2.5 配置前端 `web/.env`

前端开发环境主要变量：

| 变量 | 说明 | 示例 |
|------|------|------|
| `VITE_API_PROXY_TARGET` | Vite dev server 反向代理目标（指向 backend 容器） | `http://backend:8000` 或 `http://localhost:8880` |

`vite.config.ts` 会根据该变量把 `/api`、`/media`、`/static`、`/ws` 路径代理到后端。

## 7.3 Docker Compose 一键启动

### 7.3.1 服务拓扑

`docker-compose.yaml` 定义了 7 个服务：

| 服务 | 容器名 | 镜像 / 构建 | 宿主机端口 → 容器端口 | 依赖 |
|------|--------|-------------|------------------------|------|
| `db` | `solin_db` | `pgvector/pgvector:pg16` | `${DB_PORT}:5432` | — |
| `redis` | `solin_redis` | `redis:7-alpine` | `${REDIS_PORT}:6379` | — |
| `backend` | `solin_backend` | `./backend` 构建 | `${API_PORT}:8000` | db、redis（healthy） |
| `celery_worker` | `solin_celery_worker` | `./backend` 构建 | — | backend、db、redis（healthy） |
| `celery_beat` | `solin_celery_beat` | `./backend` 构建 | — | backend、db、redis（healthy） |
| `web` | `solin_web` | `./web` 构建 | `${WEB_PORT}:5173` | backend（healthy） |
| `caddy` | `solin_caddy` | `caddy:2-alpine` | `${HTTP_PORT:-80}:80`、`${HTTPS_PORT:-443}:443` | web |

### 7.3.2 backend 启动命令做的事

`backend` 容器启动时会自动按顺序执行：

1. `python manage.py migrate` — 执行数据库迁移
2. `python manage.py seed_operations_periodic_tasks` — 种子化周期任务
3. `python manage.py collectstatic --noinput` — 收集静态文件
4. 创建默认超管账号（用户名 `admin`，密码 `admin123456`，仅当不存在时）
5. `python manage.py seed_devices` — 种子化设备数据
6. `uvicorn config.asgi:application --host 0.0.0.0 --port 8000 --lifespan off` — 启动 ASGI 服务

> 首次启动较慢（依赖构建 + 迁移），后续重启秒级完成。

### 7.3.3 启动命令

```powershell
# 构建并后台启动所有服务
docker compose up -d --build

# 查看运行状态
docker compose ps

# 实时查看后端日志
docker compose logs -f backend

# 查看所有服务日志
docker compose logs -f
```

### 7.3.4 验证启动成功

| 验证项 | 访问地址 | 预期 |
|--------|----------|------|
| 后端健康 | `http://localhost:8880/api/v1/...` | 返回 JSON |
| Django Admin | `http://localhost:8880/admin/` | 出现登录页（admin / admin123456） |
| 前端页面 | `http://localhost:5175/` | 出现登录页 |
| Swagger 文档 | `http://localhost:8880/api/v1/schema/swagger-ui/` | 出现接口文档 |
| Caddy 入口 | `https://conai.chat`（需配置 hosts 与 TLS 证书） | 反向代理到 web |

## 7.4 常用开发命令

### 7.4.1 后端命令（在容器内执行）

```powershell
# 进入后端容器
docker compose exec backend bash

# 执行 Django 测试（优先 --keepdb，避免重建测试库）
docker compose exec backend python manage.py test apps.devices.tests.test_device_authorization_api --keepdb

# 执行数据库迁移
docker compose exec backend python manage.py migrate

# 生成迁移文件
docker compose exec backend python manage.py makemigrations

# 创建超级管理员
docker compose exec backend python manage.py createsuperuser

# Django shell
docker compose exec backend python manage.py shell

# 查看路由
docker compose exec backend python manage.py show_urls
```

### 7.4.2 前端命令

前端在 `web/` 目录下执行。容器内已自动 `npm install && npm run dev`，本地裸机开发时：

```powershell
cd web
npm install
npm run dev          # 开发模式，热更新
npm run build        # 生产构建（tsc -b && vite build）
npm run preview      # 预览构建产物
```

### 7.4.3 Celery 与异步任务

```powershell
# 查看 Celery worker 日志
docker compose logs -f celery_worker

# 查看 Celery beat 日志
docker compose logs -f celery_beat

# 进 worker 容器查看已注册任务
docker compose exec celery_worker celery -A config inspect registered
```

### 7.4.4 数据库与缓存

```powershell
# 连接 PostgreSQL
docker compose exec db psql -U postgres -d conai

# 连接 Redis
docker compose exec redis redis-cli

# 备份数据库
docker compose exec db pg_dump -U postgres conai > backup.sql
```

## 7.5 裸机开发模式（不推荐，仅限特殊场景）

如确需脱离 Docker 在宿主机直接开发：

### 7.5.1 后端

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install --no-index --find-links ./vendor/sherpa-onnx/wheels sherpa-onnx pypinyin

# 设置环境变量（建议用 direnv 或手动 $env:KEY="value"）
$env:DATABASE_URL="postgres://postgres:postgres@localhost:5433/conai"
$env:REDIS_URL="redis://localhost:6580/0"
# ...其他变量

python manage.py migrate
python manage.py runserver
```

### 7.5.2 前端

```powershell
cd web
npm install
npm run dev
```

> **注意**：裸机模式下需要自行启动 PostgreSQL（带 pgvector 扩展）、Redis，并保证端口与 `backend/.env` 一致。sherpa-onnx 的本地依赖较复杂，建议优先使用容器。

## 7.7 环境排障速查

| 现象 | 排查方向 |
|------|----------|
| `docker compose up` 拉镜像超时 | 检查 `PYTHON_BASE_IMAGE` 等镜像源变量，切换为可访问的镜像源 |
| backend 容器报 `ImproperlyConfigured: DATABASE_URL must be set` | 检查 `backend/.env` 是否存在并配置了 `DATABASE_URL` |
| backend 启动后 502 | 检查 `docker compose logs backend`，常见为数据库未就绪或迁移失败 |
| 前端页面打开空白 | 检查 `web/.env` 的 `VITE_API_PROXY_TARGET` 是否指向可达的后端 |
| 前端 `/api` 请求 404 | 确认 Vite 代理已生效，浏览器 Network 看请求是否走了 5175 端口 |
| Celery 任务不执行 | `docker compose logs celery_worker`，确认 worker 已注册任务、broker 可达 |
| pgvector 相关报错 | 确认 `db` 服务使用的是 `pgvector/pgvector:pg16` 而非官方 postgres |
| pre-commit 拦截提交 | 把新增的 `!` 前缀类与 `teal-*` 改为合规写法；紧急情况 `git commit --no-verify` |
| GitNexus 钩子报错 | 不影响 Git 操作，可 `GITNEXUS_AUTO_UPDATE=0` 临时关闭，再 `node .gitnexus/run.cjs status` 检查 |
| 端口冲突 | 修改根目录 `.env` 中的 `WEB_PORT` / `API_PORT` / `DB_PORT` / `REDIS_PORT` |
