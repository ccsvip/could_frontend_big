# 06 — 数据库结构说明

本章描述各 app 的数据模型、字段、外键关系与多租户隔离机制。数据库为 PostgreSQL 16 + pgvector 扩展。

## 6.1 多租户隔离机制

### 6.1.1 三道防线

1. **Model 层**：所有业务模型含 `tenant` 外键（`ForeignKey('tenants.Tenant')`），并挂 `objects = TenantManager()`。
2. **QuerySet 层**：`TenantManager`（`apps/tenants/managers.py`）按当前请求租户自动过滤 queryset。
3. **View 层**：`apps/tenants/mixins.py` 提供 mixin，create 时自动注入 `tenant`。

### 6.1.2 租户隔离测试

项目含 `test_isolation_contract` 测试，拦截漏挂 `TenantManager` 的模型。

### 6.1.3 平台级 vs 租户级模型

- **平台级模型**（无 tenant 字段）：`LLMProvider`、`LLMModel`、`ThirdPartyChatbotProvider`、`ThirdPartyChatbotApplication`、`TTSProvider`、`TTSVoice`（部分）、`EmbeddingModel`、`RerankModel`、`BailianKnowledgeConfig`、`ASRConfig`、`LLMTestSettings`、`MinioConfig`、`AppRelease`。
- **租户级模型**：所有带 `tenant FK` 的业务模型，通过 `Tenant*Grant` / `Tenant*Settings` 关联到公司。

## 6.10 数据库运维

- **迁移**：`python manage.py migrate`（容器启动自动执行）。
- **向量索引**：pgvector 扩展，chunk 表 `embedding` 字段走余弦相似度检索。
- **单例模型**：`LLMTestSettings` / `ASRConfig` / `BailianKnowledgeConfig` / `MinioConfig` / `EmbeddingModel` / `RerankModel` 强制 `pk=1`，`delete()` 为 no-op。
- **不可变字段**：`AppRelease` 创建后仅 `is_active` 与 `force_upgrade_version_code` 可改。
- **测试库**：优先 `--keepdb`，不要随意删除数据库。
