# 04 — 数据流程图

本章用文字 + ASCII 图描绘系统的关键数据流，覆盖设备运行时、语音对话、WebSocket、RAG、控制指令、第三方机器人、多租户隔离七大场景。

## 4.1 设备运行时配置流程

安卓设备启动后，通过 `X-Device-Code` 请求 `GET /api/v1/device-runtime/config/` 获取完整运行时配置。

```
Android 设备
    │
    │  GET /api/v1/device-runtime/config/
    │  Header: X-Device-Code: <deviceCode>
    ▼
devices.views.DeviceRuntimeConfigView
    │
    │  devices.services.runtime.get_runtime_device(code)
    │  → 校验设备存在、启用、未过期、智能体绑定
    ▼
组装完整运行时配置：
    ├─ 设备基础信息（code/name/location/status/is_enabled）
    ├─ 绑定的 DeviceApplication（resources/scrolling_texts/voice_tones/tts_voices/model_assets/command_groups）
    ├─ effective_agent_application（设备直接绑定优先，否则回退到 application.agent_application）
    │   └─ runtime_config()：system_prompt / temperature / max_tokens / knowledge_document_ids / knowledge_base_ids / tts_filter_* / follow_up_*
    ├─ 当前 TTS 音色（device.tts_voice + tts_voice_config）
    │   └─ 若未绑定 → 回退到公司默认音色（/ai-models/tts）
    ├─ 唤醒词（device.wake_words，含 encoded_text/boost/threshold）
    ├─ 控制指令（command_groups → control commands，含 backend_send_enabled）
    ├─ 点位（point_* 子领域）
    └─ 滚动字幕
    ▼
返回完整配置 JSON（即使仅音色变更也推送完整配置）
```

**配置变更实时推送**：后台修改设备音色/唤醒词/滚动字幕后，通过 `publish_device_event` 发布事件，订阅了 `device.runtime_config.subscribe` 的设备会收到完整配置重推。

> 关键约束：运行时配置音色字段只表示当前设备使用的音色；`/ai-models/tts` 是公司默认音色，仅在设备未绑定任何音色时兜底，设备一旦绑定音色则默认音色失效。

## 4.2 设备语音对话流程（HTTP 通道）

设备通过 `POST /api/v1/devices/{code}/voice-chat/` 发起单轮 HTTP 语音对话。

```
Android 设备
    │
    │  POST /api/v1/devices/{code}/voice-chat/
    │  X-Device-Code + body: {questionText, sessionId?, conversationId?}
    ▼
devices.views.DeviceVoiceChatView
    │
    │  1. get_runtime_device(code) + validate_runtime_application_active
    │  2. _find_annotation(questionText)  ← 精确匹配 AgentAnnotation
    │     ├─ 命中：返回 annotation.answer，更新 hit_count/last_hit_at
    │     └─ 未命中：继续
    │  3. try_dispatch_command(questionText)  ← 本地控制指令派发
    │     ├─ 命中且策略=直接执行：返回 reply_text + command_dispatch_snapshots
    │     └─ 未命中或需 LLM 确认：继续
    │  4. _generate_answer(device, questionText)
    │     ├─ retrieve_knowledge_context_with_media_and_references  ← RAG
    │     │   ├─ embedding(questionText) → pgvector 检索 KnowledgeDocumentChunk
    │     │   ├─ 可选 Rerank
    │     │   └─ 返回 knowledge_context + media_blocks + knowledge_references
    │     ├─ 组装 messages：system_prompt + knowledge_context + 历史 + user
    │     └─ LLM 生成 answer_text + answer_blocks
    │  5. record_device_chat_log(source=HTTP)
    │  6. 返回 Device Chat Contract：{deviceCode, answerText, answerBlocks, agentApplicationId, sessionId, conversationId}
    ▼
Android 设备（自行调 TTS 播报）
```

## 4.3 设备语音对话流程（WebSocket 通道）

设备通过 `/ws/realtime/` 发送 `agent.session.start`，触发完整 ASR→LLM→TTS 流式管线。这是最复杂的数据流。

```
Android 设备
    │
    │  WS connect /ws/realtime/
    ▼
config.realtime.realtime_websocket_application
    │
    │  接收 {type: agent.session.start, payload: {deviceCode, text?, sessionId?, conversationId?, requestId, traceId}}
    ▼
_handle_agent_session_start
    │
    ├─ _validate_agent_runtime_start(deviceCode)
    ├─ 初始化 RealtimeConnection（agent_session_id / mode / device_code / request_id / trace_id）
    ├─ 启动 _agent_tts_worker（消费 TTS 队列）
    ├─ 发送 agent.started
    │
    ├─ 若有 input_text（文本模式）→ _start_agent_llm_task(text)
    └─ 否则（语音模式）→ _start_agent_asr_session
        │
        ▼
    _open_agent_asr_session
        ├─ realtime_asr.resolve_asr_realtime_connection(token/deviceCode)
        ├─ get_effective_asr_config → 校验 is_active / is_asr_configured
        ├─ load_asr_replacement_pairs(tenant) / load_asr_filler_words(tenant)
        ├─ load_asr_effective_input_timeout_seconds(tenant) → 5~120s，默认 15s
        ├─ 连接上游 ASR WS（DashScope qwen3-asr-flash-realtime）
        ├─ 发送 session.update（vad_threshold / vad_silence_duration_ms）
        ├─ 启动 _agent_asr_upstream_to_client 任务
        ├─ 发送 asr.ready
        └─ _schedule_agent_asr_input_timeout（有效输入超时）
            │
            │  设备持续推送二进制音频帧
            ▼
        _handle_binary_frame → upstream.send(audio_append_event)
            │
            ▼
        _agent_asr_upstream_to_client（解析上游事件）
            ├─ input_audio_buffer.speech_stopped → 发送 asr.input_stopped(reason=vad)
            ├─ transcript（delta/final）→ 替换词/填充词过滤 → 发送 asr.transcript
            │   └─ final 且有文本 → agent_asr_has_valid_input=True → 取消超时
            │   └─ final → _schedule_agent_asr_finish（continuation window 0.8s）
            └─ session.finished → 拼接 final texts → 发送 asr.done → _start_agent_llm_task(text)
                │
                ▼
            _run_agent_llm_and_finish → _run_llm_session_body
                │
                ├─ _prepare_device_llm_session(deviceCode, questionText, payload)
                │   ├─ get_runtime_device + validate
                │   ├─ 解析 runtime_backend_type（platform_llm / third_party_chatbot）
                │   ├─ _resolve_runtime_conversation（按 sessionId/conversationId/新建）
                │   ├─ _find_annotation → 命中则 annotationAnswer
                │   ├─ retrieve_knowledge_context_with_media_and_references（RAG）
                │   └─ 组装 session dict（messages / modelConfig / ttsFilter* / ...）
                │
                ├─ 发送 llm.started
                │
                ├─ 若 annotationAnswer → 直接 llm.delta + TTS 段
                ├─ 否则 _try_dispatch_command_for_session（控制指令派发）
                │   ├─ 命中 → llm.delta + TTS 段
                │   └─ 未命中 → 继续
                │
                ├─ 按 backendType 分支：
                │   ├─ platform_llm → _stream_runtime_answer_deltas（httpx 异步流式）
                │   │   └─ 每个 delta → llm.delta + 缓冲到 TTS 段
                │   └─ third_party_chatbot →
                │       ├─ supports_streaming → _stream_third_party_session_message
                │       └─ 否则 → _send_third_party_session_message（同步）
                │
                ├─ TTS 段切分（pop_tts_text_segments，按标点/emoji/排除模式）
                │   └─ 每段 → _queue_agent_tts_segment → agent_tts_queue
                │       ▼
                │   _agent_tts_worker → _run_agent_tts_stream
                │       ├─ resolve_tts_realtime_connection
                │       ├─ resolve_realtime_tts_voice（设备音色优先，否则公司默认）
                │       ├─ tts_adapters.get_adapter_for_voice → ensure_channel(REALTIME)
                │       └─ adapter.stream_realtime_segments → tts.segment_start / tts.segment / tts.done
                │
                ├─ _append_runtime_conversation_messages（持久化 ChatMessage user+assistant）
                ├─ _record_realtime_device_chat_log(source=WEBSOCKET)
                ├─ 可选：_generate_session_follow_up_questions（追问）
                └─ 发送 llm.done（含 answerText/answerBlocks/commandDispatch/followUpSuggestedQuestions）
                │
                ▼
            _run_agent_llm_and_finish 收尾
                ├─ agent_tts_queue.put(None) → 等 worker 结束
                ├─ 发送 agent.done
                └─ close_agent_session
```

**关键设计**：

- TTS 与 LLM 并行：LLM 边产出 delta 边切分 TTS 段入队，TTS worker 边消费边播报，实现首字节低延迟。
- 会话续接：`sessionId`（`external_session.runtimeSessionId`）跨轮复用，避免每轮新建 ChatConversation。
- 上游 sessionId 复用：第三方机器人的上游 `chat_id` 由第三方响应提取并保存，详见 4.6。
- 超时保护：有效输入超时（5–120s）和 ASR continuation window（0.8s）双重保障。

## 4.4 知识库 RAG 流程

```
用户问题 questionText
    │
    ▼
apps.ai_models.services.agent_knowledge.retrieve_knowledge_context_with_media_and_references
    │
    ├─ 取 AgentApplication 绑定的 knowledge_documents / knowledge_bases（按 runtime_config）
    ├─ EmbeddingModel.load_aliyun → embedding(questionText)
    ├─ pgvector 检索 KnowledgeDocumentChunk（cosine 相似度，tenant 过滤）
    ├─ 可选 RerankModel 重排序
    ├─ 取 Top-K chunks 拼接为 knowledge_context
    ├─ 关联 KnowledgeMediaAsset → media_blocks
    └─ 返回 (knowledge_context, media_blocks, knowledge_references)
    │
    ▼
注入 messages：[{role: system, content: system_prompt}, {role: system, content: knowledge_context}, ...history, {role: user, content: questionText}]
    │
    ▼
LLM 流式生成 → answer_text + answer_blocks（含 media_blocks）
```

## 4.5 控制指令派发流程

```
ASR final transcript / 用户文本 questionText
    │
    ▼
apps.resources.services.command_dispatch.try_dispatch_command
    │
    ├─ 加载公司激活的 ControlCommand 列表（含 name / command_code）
    ├─ 计算 Control Command Match Confidence（确定性 0~1，非 ASR/LLM 概率）
    │   └─ 归一化文本对比 name + command_code
    │
    ├─ 按 Control Command Recognition Policy 路由：
    │   ├─ 高置信 → 直接执行（direct execution）
    │   │   ├─ backend_send_enabled=True → 后端发 TCP/UDP
    │   │   └─ backend_send_enabled=False → 客户端自送，后端不发
    │   │   └─ 配置 reply + TTS 立即继续
    │   ├─ 中置信 → LLM 确认（llm confirmation）
    │   └─ 低置信 → 普通对话（ordinary conversation）→ 走 LLM
    │
    └─ 返回 DispatchOutcome（hit / route / reply_text / matched_command_metas / tool_calls_summary）
    │
    ▼
build_command_dispatch_snapshots → Command Dispatch Snapshot（含 backendSendEnabled + 执行结果）
    │
    ▼
llm.done payload.commandDispatch = {hit, mode, replySource, toolCalls, commands, highestScore, ...}
```

## 4.6 第三方机器人集成流程

详见 [wiki/第三方机器人上下文集成指南.md](file:///c:/code/SVN_CODE/branches/real/could_frontend/wiki/第三方机器人上下文集成指南.md)。

### 方案 A（先创建会话再发消息）

```
首轮：
    ├─ ThirdPartyChatbotIntegration.config 含「创建会话」步骤 + skipWhenVariableExists
    ├─ 调用创建会话 API → 响应 extract 上游 sessionId
    ├─ 保存到 ChatConversation.external_session（按厂商字段/路径）
    └─ 调用发消息 API（携带上游 sessionId）

后续轮：
    ├─ skipWhenVariableExists 命中 → 跳过创建会话步骤
    └─ 直接复用上游 sessionId 发消息
```

### 方案 B（单 chat 接口自动创建/续接）

```
首轮：
    ├─ 请求体模板 sessionId 变量缺失 → nullWhenMissingVariables → 发送 JSON null
    ├─ 第三方自动创建会话，响应返回上游 sessionId
    └─ 保存到 ChatConversation.external_session

后续轮：
    ├─ 请求体模板回传上游 sessionId
    └─ 第三方续接同一会话
```

> 关键纪律：发给第三方的上游会话 ID 必须来自第三方响应，不得把本地 `runtimeSessionId` / 安卓 sessionId 当作第三方 sessionId 发送。

## 4.7 多租户数据隔离流程

```
请求进入
    │
    ▼
TenantAwareJWTAuthentication（JWT）/ X-Device-Code 解析
    │
    ├─ 解析出 request.tenant（或 device.tenant）
    ▼
ViewSet / Service
    │
    ├─ Model.objects（TenantManager）→ queryset.filter(tenant=request.tenant)
    │   └─ 普通公司账号：强制过滤，query 参数无法越权
    │   └─ 平台管理员：通过 tenant scope 机制浏览
    │
    ├─ create：mixins 自动注入 tenant
    └─ 跨租户写操作被拒绝
```

## 4.8 WebSocket 命令路由总览

`/ws/realtime/` 单一入口，通过 `type` 路由（详见 [05-API接口文档](./05-API接口文档.md)）：

```
客户端发送 type                    → 服务端响应 type
─────────────────────────────────────────────────────
ping                              → pong
devices.events.subscribe          → devices.events.subscribed / devices.event
devices.events.unsubscribe        → devices.events.unsubscribed
device.runtime_config.subscribe   → device.runtime_config.subscribed（完整配置）
device.runtime_config.unsubscribe → device.runtime_config.unsubscribed
device.status.start               → device.status.started / device.status
device.status.ping                → device.status.pong
device.voice.bind                 → device.voice.bound + device.voice_configuration.changed
asr.session.start                 → asr.ready / asr.transcript / asr.input_stopped / asr.done
asr.session.finish                → （触发 ASR 收尾）
asr.session.cancel                → asr.cancelled
tts.session.start                 → tts.segment_start / tts.segment / tts.done
tts.session.cancel                → tts.cancelled
llm.session.start                 → llm.started / llm.delta / llm.tts_segment / llm.done
llm.session.cancel                → llm.cancelled
agent.session.start               → agent.started / asr.* / llm.* / tts.* / agent.done
agent.session.finish              → （触发 ASR→LLM 收尾）
agent.session.cancel              → agent.cancelled
```

错误统一为 `error` / `asr.error` / `tts.error` / `llm.error` / `agent.error`，携带 `error.code` + `error.message` + `requestId` + `traceId`。
