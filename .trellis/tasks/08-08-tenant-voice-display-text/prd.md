# 公司音色试听文本覆盖

## 目标

让公司 Web 管理员可为本公司每个已获授权的 TTS 音色保存独立试听文本。公司未配置时，试听使用超管在供应商设置中维护的默认试听文本；试听文本只影响公司 Web 的测试播放，不改变音色、合成参数或设备运行时行为。

## 已确认事实

- 公司侧 TTS 页面路径为 `/ai-models/tts`；超管 CosyVoice 配置页面路径为 `/settings/tts/cosyvoice`。
- 超管当前通过 `CosyVoiceSettings.default_test_text` 维护全局默认试听文本；公司 options 顶层 `defaultTestText` 当前来自选中默认音色所属卡片的供应商配置。
- 公司 `POST /api/v1/ai-models/tts/test/` 已支持 `voiceId` 和自定义 `text`；请求 text 为空时由后端回退供应商默认试听文本。
- 公司音色可用性由统一 TTS 授权服务决定；设备码只能读取 options，不能写入公司管理配置。

## 数据流

超管供应商默认试听文本 + 公司 `(tenant, voice)` 试听文本覆盖 → 认证公司 Web options 的每个 voice 返回有效 `testText` → 公司 TTS 页面选择音色时填充试听输入框 → 公司 TTS 测试 API 以该文本试听。

设备码 options、设备运行时、实时 WebSocket 和 TTS 合成配置不读取或携带公司试听文本覆盖。

## 需求

### R1 公司级、音色级覆盖

1. 公司 TTS 更新权限用户可为每个当前已获授权音色保存一条试听文本。
2. 同一音色在不同公司可保存不同文本，读取严格按当前请求租户隔离。
3. 未配置覆盖时，`testText` 使用超管维护的供应商默认试听文本。
4. 清空覆盖后删除记录，立即恢复供应商默认文本；不保存空字符串覆盖。
5. 文本首尾空白应去除；保存后文本长度为 1–2000 字符。

### R2 公司 Web 行为

1. `/ai-models/tts` 的音色目录为每个音色提供“编辑试听文本”入口。
2. 选择音色后，试听输入框默认显示该音色的有效 `testText`，用户仍可临时修改后试听。
3. 保存或恢复默认后刷新 options，当前音色的试听输入框立即反映新值。
4. 超管配置页继续维护供应商默认试听文本；不显示或修改公司覆盖。

### R3 API 与权限

1. `GET /api/v1/ai-models/tts/options/` 的认证 Web 响应为每个 voice 增加：
   - `testText`：当前公司的有效试听文本；
   - `customTestText`：当前公司的音色覆盖文本；未配置时为空字符串；
   - `platformTestText`：供应商默认试听文本；
   - `hasTestTextOverride`：是否存在公司覆盖。
2. 设备码 options 保持现有字段和值，不返回上述新增字段，也不读取公司覆盖。
3. 新增 REST 资源：
   - `PUT /api/v1/ai-models/tts/voice-test-texts/{voiceId}/`，请求 `{"testText": "..."}`；
   - `DELETE /api/v1/ai-models/tts/voice-test-texts/{voiceId}/`，返回 `204`。
4. 租户从认证上下文取得；写入前必须调用统一授权入口。未知、未授权、停用、下架或其他公司私有音色使用现有统一错误。
5. 设备码、超管账号和无公司 TTS 更新权限用户不能写入覆盖。
6. 公司测试 API 在请求 text 为空且指定 `voiceId` 时，应使用该公司该音色的有效 `testText`；显式传入 text 仍优先，仅 Web 测试接口使用覆盖。

### R4 业务不变性

音色编码、默认音色、卡片与音色授权、合成参数、CosyVoice 配置、设备绑定、设备运行时配置、实时通知和设备码 options 保持既有行为。

## 验收标准

- [ ] 公司为两个已授权音色保存不同试听文本，选择对应音色时分别显示并试听各自文本。
- [ ] 两家公司对同一音色保存不同文本，options 与测试请求严格按租户隔离。
- [ ] 未配置或删除覆盖后，Web options 和试听输入框回退超管默认试听文本。
- [ ] 超管修改默认试听文本后，未覆盖公司立即使用新文本；已覆盖公司不受影响。
- [ ] 未授权、其他公司私有或不存在音色写入被统一拒绝且不产生记录；无更新权限不可写。
- [ ] 设备码 options、默认音色保存、设备运行时、实时 TTS 和超管试听既有契约不变。
- [ ] 后端目标 Django 测试与前端 `npm run build` 通过。

## 范围外

- 为 Android 或设备运行时提供公司试听文本。
- 修改 TTS 供应商参数、音色编码、音色授权、默认音色选择或 CosyVoice 合成协议。
- 把试听文本自动用于实时对话或非测试合成请求。
